CP firmware
===========

The firmware of the command processor's control processor (`atg_cpu`,
RV32IM, spec/gpu/cp/atg_cpu.md): it takes the class V packets of the ring,
decodes the gpu-ops of zedBSD's GPU command protocol, keeps the Vulkan
objects of each session and gives the sequencer class N µops through the
window's UOP_FIFO (design §2.4.4-§2.4.9 and §6.9).  Wire form of the
packets and results: `include/ghci_frame.h`; image layout:
`include/ghci_layout.h`; the GHCI gpu-ops: docs/ghci.md section 7.

Build
-----

`tools/fw-build.sh` compiles with the shared LLVM (clang `--target=
riscv32-unknown-elf -march=rv32im -mabi=ilp32 -ffreestanding -fno-builtin
-nostdlib -Oz -Wall -Wextra -Werror`, linker relaxation on, used
read-only) and writes the BRAM init images
`images/atg1-cp-kc705.{imem,dmem}.hex` (64-byte AMB lines, IMEM 32768 and
DMEM 8192 words).  The images are committed: the simulation
(`sim/tb/atg_top_fw_tb.v`, `sim/verilator/fw-run.sh`) and the Vivado build
read them without a compiler; run the script after changing the firmware.
There is no compiler-rt for riscv32 in the shared LLVM, so `lib.c` carries
memcpy, memset, memcmp, the 64-bit shifts and the 64-bit division, and
`float.c` the few fp32 operations.

The LLVM is found at `CLANG_BIN`, by default `../zedBSD-claude1/build/llvm/bin`
beside the repository's root (`tools/cpu-tests.sh` likewise).  From a
checkout elsewhere, such as a git worktree, pass it:
`CLANG_BIN=/path/to/llvm/bin tools/fw-build.sh`.

`formats.inc` (the formats of tools/fmtmodel.py) and `programs.inc` (the
built-in GSI1 programs of `programs/`, assembled by tools/gsi1asm.py) are
generated by `tools/fw-formats.py` and `tools/fw-programs.py` and
committed.

Behaviour
---------

- The firmware polls (PKT_INFO, IRQ); it does not use WFI and interrupts:
  an interrupt between unmasking IRQ_EN and a WFI would return to a WFI
  nothing wakes.
- Start-up: CPFW_STATUS[15:8] 1 (boot) then 2 (idle), CPFW_VERSION
  0x0002_0000, MBOX3 = 0x0DA7A001 (a `.data` word, checked to be restored
  after RESET).  A packet: state 3.  A halt request between packets: PARK
  (state 4) until the halt ends.  The heartbeat writes FW_STATUS every 1024
  polls (CPFW_STATUS.ALIVE toggles).
- A packet is `[gpu-op][flags][result address][arguments]`.  GHCI_FRAME
  points at a frame of records `[number][flags][result index][arguments]`
  in the staging buffer; each record's `{VkResult, aux}` goes to the result
  page as it is decoded, the frame's own `{VkResult, records decoded}` to
  the packet's result address (flags RESULT), then IRQ_STATUS.RESULT, then
  the submits' replays, then DONE.  A number the firmware does not know ends the frame with
  VK_ERROR_FEATURE_NOT_PRESENT (the wire has no lengths, the next record
  cannot be found).
- The heap: GHCI_HEAP `[u64 address][u64 bytes][u32 resident warps]`
  lends a range of GPU memory, which the firmware hands out in lines; the
  third word (the GPU's RESIDENT_WARPS) sizes scratch memory.  The driver
  lends the heap once, before it opens a session.
- Recorded commands become µop packets at record time, in the command
  buffer's recording, with the constant bank's image as data; a uniform
  block's words are copied into the bank by a recorded blit when the
  recording runs.  QUEUE_SUBMIT checks its command buffers and lists
  them; the replays run in ring order after the packet's results (the
  host's vkQueueSubmit returns while the units work) or before the next
  record of the frame that is not a submit, and DONE follows them, so
  the driver's FENCE still follows the work.  A replay that fails then
  loses its session (its later submits answer VK_ERROR_DEVICE_LOST);
  what the replay must do itself (an indirect draw's counts, a copy of
  query results) is a marker in the recording.
- Images are linear (`ghci_layout.h`); a view gives a texture slot's
  words (TEX_ROW 1 for the attachment layout) and a render target's.
- Transfers are blits; copies of the stencil aspect are the built-in
  compute programs, and vkCmdBlitImage with scaling or a format change
  is the built-in draw.

Limits and later work
---------------------

- Descriptor arrays: only element 0 of an array binding reaches a
  program (the compiler's limit).
- Timestamps are not offered (timestampValidBits 0); cube-map arrays are
  not offered.
- An odd-width attachment image is sampled right only once the texture
  unit reads TEX_ROW.
- STEP of a class V packet in HALTED does not run: the core is parked while
  CTRL.HALT is 1.
- The codec is written by hand; design §2.4.8 generates it from one table
  with the driver (`ghci_vkwire.inc`).
- The image needs the KC705's CPU memories (128 KiB IMEM, 32 KiB DMEM); a
  smaller board needs a smaller firmware.

Tests
-----

- `fw/cp/tests/run.sh`: the firmware built for the host against a model
  of the window, the DMA, the sequencer's SET_REG and the blitter; six
  cases (sessions, buffers, images, a draw in the command sequence of a
  vkdemo frame, compute, transfer) check the result records, the µops,
  the STATE and the memory; `kernels.py` runs the built-in compute
  programs on tools/gsi1model.py.
- `sim/tb/atg_top_fw_tb.v` (iverilog): the image in atg_top, a frame
  through the ring, CPFW RUN, RESET and LOAD.
- `sim/verilator/fw-run.sh`: the host cases' trace (`fwtest -t`) replayed
  on atg_top with the CPU and the units; the µop words the CPU gives the
  sequencer, the result words and the STATE compared with the host's.
