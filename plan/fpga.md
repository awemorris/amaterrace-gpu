# FPGA ハードウェア構造と RTL 設計規則ガイドライン

本書は、Amaterrace GPU プロジェクトにおいて FPGA（AMD/Xilinx 7 シリーズ、Kintex-7 XC7K325T 等）をターゲットとした RTL 設計およびコーディングを行うすべてのサブエージェント（P1〜P8）および開発者が遵守すべき **必須前提知識・厳格な実装規則** を定めたものである。

コーディング担当エージェントは、一般的な Verilog 文法知識だけでなく、**「FPGA の物理シリコン上でどのように配置・配線（P&R）されるか」** を完全に理解した上でコードを記述しなければならない。

---

## 1. なぜ FPGA で乗算演算子 `*` を書いてはならないのか？

### 1.1 論理合成ツール（Vivado）による自動推論の限界と罠
Verilog で `assign m = a * b;` と記述すると、論理合成ツール（Vivado）はヒューリスティックに基づいて演算器を自動推論（Inference）します。
しかし、以下の致命的な問題が発生します：
1. **意図しないファブリック LUT 加算器への分散**:
   オペランド幅が DSP 1 個（符号付き $25 \times 18$、符号なし $24 \times 17$）を超える大きな乗算（24×24, 24×59, 33×33, 42×42 等）において、合成ツールは部分積の加算を「通常のファブリック LUT / CARRY4 加算器」に追い出してしまいます。
2. **配線遅延（Routing Delay）の爆発とタイミング破綻**:
   ファブリック配線は配線遅延が極めて大きく、大量の LUT ロジックスライスを浪費します。その結果、動作周波数（目標 200 MHz）の達成が物理的に不可能になります。

### 1.2 専用シリコンブロック「DSP48E1」と縦列カスケード配線
FPGA（Xilinx 7 シリーズ）の物理ダイ上には、通常のロジックセル（LUT）とは独立した「DSP48E1」ハードウェアスライスの専用縦列（Column）が存在します。
- スライス同士は、隣接するスライス間で **専用の 48 ビット高速カスケード配線（`PCOUT -> PCIN`）** によって物理的に直結されています。
- この専用カスケード配線はファブリック配線を一切通らず、遅延がほぼゼロ（約 0.1 ns）です。
- **原則**: この専用シリコンの性能を 100% 引き出し、ファブリック加算器および配線遅延を完全ゼロにする唯一の方法が、Verilog で **プリミティブ `DSP48E1` を直接インスタンス化（Direct Instantiation）** することです。ソースツリーにおいて乗算演算子 `*` の推論に依存してはなりません。

## 2. DSP48E1 の物理構造と内部パイプラインレジスタ

DSP48E1 の内部は、**入力レジスタ (`AREG/BREG`) → $25 \times 18$ 乗算器 → 乗算後レジスタ (`MREG`) → ポスト加算器 (ALU) → 出力レジスタ (`PREG`)** という専用の超高速パイプライン構造になっています。

```text
       A [29:0]           B [17:0]
          │                  │
     ┌────▼────┐        ┌────▼────┐
     │  AREG   │        │  BREG   │  <-- 入力レジスタ段 (LAT=3 で有効)
     └────┬────┘        └────┬────┘
          └────────┬─────────┘
                   │
             ┌─────▼─────┐
             │ 25x18 Mult│
             └─────┬─────┘
                   │
             ┌─────▼─────┐
             │   MREG    │           <-- 乗算後レジスタ段 (LAT>=2 で有効)
             └─────┬─────┘
                   │
    PCIN [47:0] ───┼──────────┐
    (from lower)   │          │
             ┌─────▼──────────▼─────┐
             │ ALU / Post-Adder     │ (OPMODE で加算・17bitシフト加算を制御)
             └──────────┬───────────┘
                        │
                  ┌─────▼─────┐
                  │   PREG    │      <-- 出力レジスタ段 (LAT>=1 で有効)
                  └─────┬─────┘
                        ├──────────────────────── PCOUT [47:0] (to upper DSP)
                        ▼
                     P [47:0]
```

### 2.1 やってはならない致命的アンチパターン（ファブリックでの遅延）
> [!CAUTION]
> **DSP48E1 の内部レジスタをバイパス（`AREG=0, BREG=0, MREG=0, PREG=0`）にしたまま、出力をファブリックに出してから `always @(posedge clk) r <= p_comb;` とファブリックのフリップフロップ（FF）で遅延させる記述は、FPGA 設計において絶対に禁止します。**

ファブリックで遅延させると、DSP 内部の長い伝搬遅延＋ファブリックへの長距離配線遅延がそのままクリティカルパスになり、DSP 内蔵の超高速レジスタが無駄死にします。

### 2.2 パイプライン段数 `LAT` と DSP 内部レジスタの厳格な対応
`am_mul.v` などの演算器モジュールにおいて、遅延パラメータ `LAT`（0〜3）は **必ず DSP48E1 内部のレジスタ属性パラメータに 1 対 1 で直結** させなければなりません（`LAT <= 3` の場合、ファブリックレジスタは 0 個）：

| `LAT` 設定 | `AREG` / `BREG` | `MREG` | `PREG` | 物理的動作 |
| :---: | :---: | :---: | :---: | :--- |
| **LAT = 0** | **0** | **0** | **0** | 完全組合せ回路（スルー）。クロック遅延なし。 |
| **LAT = 1** | **0** | **0** | **1** | 出力レジスタ `PREG` のみ有効。P および PCOUT を 1 サイクル遅延。 |
| **LAT = 2** | **0** | **1** | **1** | 乗算器直後の `MREG` と出力 `PREG` を有効化。乗算と加算をパイプライン分割。 |
| **LAT = 3** | **1** | **1** | **1** | 入力 `AREG/BREG`、中間 `MREG`、出力 `PREG` を全段有効化（最高周波数）。 |

※クロックイネーブル信号 `en` は、有効化されたレジスタ段の `CEA2`, `CEB2`, `CEM`, `CEP` に接続し、クロックゲーティングを行ってください。

## 3. タイリング分割と `PCOUT -> PCIN` カスケードの正確な結線

### 3.1 符号なし乗算の入力幅制限（$24 \times 17$ ビット）
DSP48E1 の乗算器は符号付き $25 \times 18$ です。
符号なし乗算（Unsigned）を正しく計算するには、最上位ビットが符号（負数）と誤認されないよう、**A ポートは最大 24 ビット（`A[23:0]`）、B ポートは最大 17 ビット（`B[16:0]`）** までしか入力できません（最上位ビットには `1'b0` をゼロ拡張）。
したがって、幅がこれを超える乗算は **17 ビット単位** でタイル分割します。

### 3.2 OPMODE の設定規則（最重要）
DSP48E1 の `OPMODE[6:0]` は、ポスト加算器（ALU）の X, Y, Z 入力マルチプレクサを制御します：
- `OPMODE[1:0]` = X MUX: `2'b01` = 乗算器出力 $M$
- `OPMODE[3:2]` = Y MUX: `2'b00` = 0（加算なし）
- `OPMODE[6:4]` = Z MUX:
  - `3'b000` = 0（加算なし、初段スライス用）
  - `3'b001` = `PCIN` そのまま加算（同重みの部分積加算）
  - `3'b101` = **`PCIN` を 17 ビット右シフトして加算（重みが 17 ビット上位のスライス）**

したがって、OPMODE は以下の 3 通りのみを使用します：

```verilog
// 1. 初段スライス (重み 0): P = M
OPMODE = 7'b0000001; // Z=000, Y=00, X=01

// 2. 17 ビット上位へシフトするカスケード段: P = M + (PCIN >> 17)
OPMODE = 7'b1010001; // Z=101, Y=00, X=01

// 3. 同重みの部分積を加算するカスケード段: P = M + PCIN
OPMODE = 7'b0010001; // Z=001, Y=00, X=01
```

> [!WARNING]
> `OPMODE` の Y MUX に `2'b01` を設定してはなりません（不正な設定）。必ず上記コードのビットパターンを使用してください。

### 3.3 最終積のビット引き出し
- 直列カスケードにおいて、重み $17 \times k$ の最終段スライスの出力 `P[16:0]` が、そのまま最終積のビット `[17*k +: 17]` となります。
- 最上位スライスの `P` からは、残りの上位全ビットをそのまま取り出します。
- **ファブリック加算器（`+`）は 1 ビットも使用してはなりません。すべて DSP 内部の ALU が PCOUT/PCIN 経由で加算しきります。**

## 4. 全インスタンス構成の標準設計パターン

本 GPU の RTL で使用される全幅におけるタイル・カスケード構成：

1. **1 DSP** (A_S <= 25 && B_S <= 18):
   - 8×8, 9×9, 16×8, 8×17, 16×16, 17×16, 16×17, 24×17 unsigned 等。
   - `OPMODE = 7'b0000001`
2. **2 DSP 1×2 カスケード** (片軸 <= 24 unsigned, 他軸 18..34 unsigned):
   - 18×18, 24×24, 32×3, 32×16, 17×32 unsigned, 25×25, 27×17, 30×17 signed。
   - DSP 0 (低位): `OPMODE = 7'b0000001` -> `PCOUT`
   - DSP 1 (高位): `OPMODE = 7'b1010001`, `PCIN = DSP0.PCOUT`
   - 積: `{ DSP1.P[AW+BW-18:0], DSP0.P[16:0] }`
3. **4 DSP 1×4 カスケード** (24×59 unsigned, `atg_su_xu u_tp`):
   - A=24, B=17+17+17+8 の 4 段直列カスケード。
4. **4 DSP 2×2 カスケード** (33×33 signed, `atg_su_fpu`, `atg_cpu_muldiv`):
   - A=17+16 signed, B=17+16 signed の 4 段。
5. **9 DSP 3×3 カスケード** (42×42 unsigned, `atg_su_xu u_prod`):
   - A=17+17+8, B=17+17+8 の 9 段直列カスケード。

- [ ] ソースツリー内に信号乗算演算子 `*` が書かれていないか？
- [ ] `am_mul.v` は `DSP48E1` プリミティブを真に直接インスタンス化しているか？
- [ ] `LAT` パラメータに応じて、`AREG/BREG`, `MREG`, `PREG` が正しく 0 または 1 に設定されているか？
- [ ] ファブリックで `p_comb` をレジスタ遅延させるような記述が完全ゼロになっているか？
- [ ] `PCOUT -> PCIN` カスケードの `OPMODE` は正しいビットパターン（`7'b0000001`, `7'b1010001`, `7'b0010001`）になっているか？
- [ ] `./tools/mul-dsp-test.sh`（76 インスタンス等価検証）が全件 PASS しているか？
- [ ] `tools/arith-lint.py` および `tools/lint.sh` が 0 エラーで通過しているか？
