ZCU106 (XCZU7EV-2FFVC1156-E)
============================

`atg_zcu106_top`: Top-level board support package for the AMD / Xilinx ZCU106
Evaluation Kit featuring the Zynq UltraScale+ XCZU7EV MPSoC.

Architectural Overview
----------------------

### 1. Clocking & Reset
- **GPU Core Logic Clock (`clk_gpu`)**: 400.0 MHz (period 2.500 ns).
- Synthesized from the 100.0 MHz PS reference clock (`pl_clk0`) using an
  on-chip UltraScale+ `MMCME4_BASE` primitive (`boards/zcu106/lib/atg_zcu106_clk.v`):
  - CLKIN = 100.0 MHz (DIVCLK_DIVIDE = 1)
  - CLKFBOUT_MULT_F = 12.000 -> VCO = 1200.0 MHz (well within 800–1600 MHz limits)
  - CLKOUT0_DIVIDE_F = 3.000 -> 400.0 MHz (`clk_gpu`)
  - CLKOUT1_DIVIDE = 6 -> 200.0 MHz (`clk_axi`, optional synchronous AXI clock)
- Active-low synchronous resets (`rst_n_gpu`, `rst_n_axi`) generated by gating
  external reset with MMCM `LOCKED` output through `am_sync` synchronizers.

### 2. Memory Architecture (UMA)
- **Unified Memory Architecture (UMA)**: The GPU operates exclusively using
  the PS host DDR4 memory. There is no dedicated VRAM, MIG controller, or
  AXI memory split logic on the board.
- The GPU Memory Controller master port connects directly to the Zynq MPSoC
  High-Performance slave port `S_AXI_HP0_FPD`:
  - Native 128-bit AXI4 data bus (`DATA_W = 128`).
  - Native 64-byte cache line geometry (`LINE_BYTES = 64`, `LINE_SHIFT = 6`),
    corresponding to 4-beat bursts of 128-bit transfers.
  - Parameters: `LOCAL_BASE = 0`, `LOCAL_BYTES = 0`, `WINDOW_BYTES = 0`,
    `HOST_LIMIT = 0` (all physical addresses route to host DRAM via AxID 1).

### 3. Host Interface & Interrupt
- **Canonical MMIO BAR0**: Mapped from the PS Full-Power Domain AXI master
  `M_AXI_HPM0_FPD` directly to the GPU slave interface:
  - 64-bit data bus, 17-bit register address space (`[16:0]`).
  - Isolated from the 400 MHz GPU core clock domain by a low-latency
    asynchronous AXI CDC bridge (`am_axi_cdc`).
- **PCIe**: Not used.
- **Interrupt (`pl_ps_irq0`)**: GPU level-sensitive interrupt line (`irq`)
  is synchronized to the PS AXI clock domain via `am_sync` and fed directly
  to the ARM GIC.

### 4. GPU Configuration (Minimal Preset)
Derived from `config/minimal.mk`:
- `NSU = 1`: 1 Shader Unit.
- `SU_NPHYS = 4`, `SU_NWARPS = 4`, `SU_NREGS = 32`.
- `SU_LDS_BYTES = 1024` (1 KB Local Data Share).
- `SU_PACKED = 0`: Packed FP16 arithmetic disabled.
- `MS4 = 0`: MSAA disabled (1x only).
- `ROP_STENCIL = 1`: Depth/stencil support enabled.
- `HAS_L2 = 1`, `L2_WAYS = 4`, `L2_SET_W = 5` (8 KB L2 cache).
- `VA_BITS = 30`: 1 GiB GPU virtual address space.
- `PA_BITS = 40`: 1 TiB host physical address space.

Board Pinout & Constraints
--------------------------

- Pin constraints and clock definitions are in `atg_zcu106_top.xdc`.
- **User LEDs**: 8 active-high status LEDs on HP Bank 66/67 (1.2 V LVCMOS12):
  - `led[0]` (AL11): MMCM locked
  - `led[1]` (AL13): GPU core reset active (inverted `rst_n_gpu`)
  - `led[2]` (AK13): GPU interrupt pending (`gpu_irq`)
  - `led[3]` (AE15): GPU active (busy status)
  - `led[4]` (AM8) : S_AXI AW transaction handshake
  - `led[5]` (AM9) : S_AXI AR transaction handshake
  - `led[6]` (AM10): M_AXI AW transaction handshake
  - `led[7]` (AM11): M_AXI AR transaction handshake

Generation & Build
------------------

- IP cores (Zynq MPSoC block) generated via:
  ```sh
  vivado -mode batch -source boards/zcu106/ip.tcl -tclargs OUT
  ```
- Top-level synthesis & implementation:
  ```sh
  VIVADO_IP=OUT tools/vivado-build.sh zcu106 atg_zcu106_top
  ```
  *(Note: Vivado synthesis is not run during active runs of other agents)*
